The TMS project repository (`TMS/tms`) is structured as a monorepo containing three core application services (`api`, `web`, `volksAi`), alongside monitoring and deployment configurations.

## Root Directory Overview

```
TMS/tms/
├── api/                        # NestJS 11 backend application (Node.js / TypeScript)
├── web/                        # React 19 Single Page Application (Vite 7 / TypeScript)
├── volksAi/                    # FastAPI microservice for AI & PDF processing (Python 3.11+)
├── tms-docs/                   # Mintlify developer documentation site
├── grafana-dashboard-defs/     # JSON definitions for Grafana dashboards
├── logs/                       # Shared log directory for file-based rotating logs
├── docker-compose.yml          # Multi-container orchestration (Postgres, Redis, Loki, Grafana)
├── loki-config.yml             # Grafana Loki log aggregation configuration
└── promtail-config.yml         # Promtail log shipping agent configuration
```

## 1. Backend Service (`api/`)

The NestJS backend manages 29 feature modules, business logic, authentication, database migrations, and background BullMQ workers.

```
api/
├── drizzle/                    # SQL migrations generated by Drizzle Kit (0000-0161)
├── drizzle.config.ts           # Drizzle migration and database connection config
├── src/
│   ├── main.ts                 # HTTP bootstrap, CORS, validation pipe, exception filter
│   ├── worker.ts               # BullMQ worker entrypoint (orchestrates 5 background workers)
│   ├── app.module.ts           # Root module importing all 29 feature domains
│   ├── config/                 # Strongly-typed, Zod-validated configuration modules
│   ├── db/
│   │   ├── database.module.ts  # Database connection pool and Drizzle provider
│   │   ├── seed.ts             # Initial database seed for admin roles and master tables
│   │   └── schemas/            # 125 schema files categorized by domain
│   │       ├── auth/           # users, roles, permissions schemas
│   │       ├── tendering/      # tenders, info-sheets, extractions, checklists
│   │       ├── operations/     # purchase orders, work orders, contracts, inventory
│   │       ├── accounts/       # imprests, loans, bank guarantees, FDRs
│   │       ├── master/         # shared entities (clients, teams, statuses)
│   │       └── shared/         # claude_token_usage, file uploads
│   └── modules/                # Feature controllers, services, and DTOs
│       ├── tendering/          # RFQs, costing, bids, reverse auctions, info-sheets
│       ├── checklists/         # BiddingRequirementsService & checklist jobs
│       ├── master/health/      # System health checks, DB table verification
│       └── notifications/      # Email and WhatsApp notification dispatchers
└── test/                       # Jest unit and end-to-end test suites
```

## 2. Frontend Application (`web/`)

The frontend is a single-page application built on React 19, Vite 7, and Tailwind CSS v4, utilizing AG Grid for high-density enterprise data tables.

```
web/
├── src/
│   ├── main.tsx                # App entrypoint wrapping QueryClient, Auth, and Theme providers
│   ├── App.tsx                 # Client-side router definition
│   ├── components/             # Reusable UI widgets, modals, badges, form inputs
│   ├── modules/                # 20 feature domains mirroring API modules
│   │   ├── tendering/          # InfoSheetForm, ExtractionPreviewPanel, checklists UI
│   │   ├── operations/         # Work orders, purchase orders, contracts
│   │   ├── accounts/           # Bank guarantees, FDRs, financial instruments
│   │   └── dashboard/          # Executive, team, and procurement analytics
│   ├── services/api/           # Typed Axios HTTP client wrappers calling the NestJS API
│   ├── hooks/                  # React Query hooks and custom application hooks
│   └── types/                  # TypeScript interfaces mirroring API DTOs
├── tailwind.config.ts          # Tailwind v4 theme styling rules
└── vite.config.ts              # Bundler config with reverse-proxy from /api to :3000
```

## 3. VolksAI Microservice (`volksAi/`)

A high-throughput Python FastAPI microservice dedicated to reading messy PDF tenders, parsing tables, and resolving legal clauses via Anthropic Claude.

```
volksAi/
├── app/
│   ├── main.py                 # FastAPI app initialization, middleware, CORS, lifespan hooks
│   ├── routers/
│   │   ├── extract.py          # POST /extract (Tender PDF ingestion & field extraction)
│   │   ├── bidding_requirements.py # POST /analyze-bidding-requirements (Checklist analysis)
│   │   └── health.py           # GET /health (Microservice and Anthropic readiness)
│   ├── services/
│   │   ├── pdf_parent_ingest.py    # PyMuPDF & pdfplumber extraction, OCR fallback
│   │   ├── tender_mapper.py        # Layer 1 deterministic regex mapping
│   │   ├── field_extractor.py      # Spatial table and text parser
│   │   ├── llm_field_resolver.py   # Layer 2 Claude resolver (Role 1 Haiku & Role 2 Sonnet)
│   │   └── tms_field_mapper.py     # Converts Python dicts to standard NestJS camelCase DTOs
│   └── core/                   # Logging, configuration settings, error handlers
├── scratch/                    # Diagnostic scripts, test fixtures, model pings
├── Dockerfile                  # Container definition with PyMuPDF and PaddleOCR
└── requirements.txt            # Python dependencies
```

## 4. Shared Storage & Observability

* **`logs/`**: Both NestJS and FastAPI write rotating logs to this shared folder (`api.log`, `api-error.log`, `volksai.log`).
* **`promtail-config.yml`**: Configures Promtail to tail log files in `logs/` and stream them to Loki.
* **`docker-compose.yml`**: Provides single-command initialization for PostgreSQL, Redis, Loki, Promtail, and Grafana.
