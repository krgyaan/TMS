The core workhorse of VolksAI is **`tender_mapper.py`** (242 KB), an extensive, deterministic rule-based parsing engine. It is designed to extract commercial, financial, and operational fields from structured tables and Bid Data Sheets **without calling any LLM API**.

## Why Layer 1 Runs First

* **Zero Token Cost:** 100% of Layer 1 computations run locally on CPU.
* **Sub-Second Execution:** Processes a standard 50-page GeM tender in **1.2 to 1.8 seconds**.
* **Zero Hallucination Risk:** Regex and spatial layout match exact character sequences and structured grid cells.
* **High Coverage:** Over **65% of standardized tender fields** are resolved entirely within Layer 1.

## 1. GeM Table Spatial Parsing

Government e-Marketplace (GeM) bid documents follow a predictable multi-column key-value layout:

```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│ Bid End Date/Time                    │ 15-11-2026 15:00:00                  │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ Bid Opening Date/Time                │ 15-11-2026 15:30:00                  │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ Department Name                      │ GAIL (India) Limited                 │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ Total Quantity                       │ 1                                    │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ EMD Amount                           │ 900000.00                            │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

`tender_mapper.py` and `field_extractor.py` extract these cells using coordinate-aware row and column alignments:
1. Detect horizontal bounding boxes separating rows.
2. Split cells into label column (left) and value column (right).
3. Match labels against the **Field Alias Registry**.

## 2. Field Alias Registries

Different procurement portals and PSUs use slightly different labels for the same commercial parameter. VolksAI maps these variants to canonical internal field keys:

### GeM Standard Aliases (`gem_field_aliases.py`)
* **Tender Number:** `"bid number"`, `"bid no"`, `"bid doc no"`, `"tender id"`, `"enquiry no"`
* **Due Date:** `"bid end date/time"`, `"bid submission deadline"`, `"due date and time"`
* **EMD Amount:** `"emd amount"`, `"earnest money deposit"`, `"bid security"`, `"bid bond"`
* **PBG Percentage:** `"epbg percentage"`, `"performance security"`, `"pbg %"`

### PSU Specific Aliases (`gail_clause_aliases.py`)
PSUs like GAIL, NTPC, and IOCL frequently introduce proprietary terminology:
* Contract Performance Security (**CPS**) is mapped to canonical `pbg_percentage`.
* Price Reduction Schedule (**PRS**) is mapped to canonical `ld_percentage_per_week`.
* Manufacturer's Authorization Form (**MAF**) is mapped to canonical `maf_required`.

## 3. Data Normalizers (`normalizer.py`)

Raw extracted text from government PDFs often contains non-standard currency units, date formats, or legal phrases. `normalizer.py` cleans and standardizes them:

### Money Normalization
Converts colloquial Indian financial units into standard float values:
* `"₹ 9.5 Lakhs"` → `950000.0`
* `"Rs. 2.4 Crore"` → `24000000.0`
* `"INR 50,00,000/-"` → `5000000.0`

### Percentage Normalization
* `"Five Percent (5%)"` → `5.0`
* `"0.5% per week or part thereof"` → `0.5`

### Date-Time Normalization
Converts dates into standard ISO-8601 strings with timezone offset (`+05:30`):
* `"15-11-2026 15:00:00"` → `"2026-11-15T15:00:00+05:30"`
