## The Single Biggest Risk to Production Readiness

<Warning>
  **Risk: Scanned PDFs & Image-Only ATC Documents**
  
  While GeM primary bid documents are 100% digital PDFs, PSUs (like State Electricity Boards, Municipal Corporations, or GAIL regional offices) frequently scan physical paper circulars and append them as the ATC PDF.
  
  * If PyMuPDF extracts 0 characters from a scanned 50-page technical specification, VolksAI relies entirely on PaddleOCR.
  * If PaddleOCR is starved of memory/CPU inside Docker or if the scan is skewed/low-resolution, Layer 1 regex will extract nothing, and Layer 2 LLM scoping will fail to find section headers.
  * **Impact:** The Tender Executive will see red `MISSING` badges for critical fields, forcing manual data entry.
  * **Mitigation:** Ensure the PaddleOCR container has at least 2GB of dedicated RAM and add an explicit "Scanned Document Detected" warning banner in the Web UI.
</Warning>

## Known Bugs & Fix Suggestions

<AccordionGroup>
  <Accordion title="Issue 1: Phone Number Whitespace in Contact Extraction (P1)">
    * **Symptoms:** Unit test `test_contact_integrity.py::test_clean_phone` fails:
      ```
      AssertionError: assert '+91-484-2983210 / 11 / 12 / 13' == '+91-484-2983210/11/12/13'
      ```
    * **Root Cause:** In `volksAi/app/services/tender_mapper.py` / `field_extractor.py`, `clean_phone()` inserts spaces around forward slashes (` / `), while standard phone normalization expects compact slashes (`/`).
    * **Fix:** Add a final regex replace pass to collapse whitespace around slashes:
      ```python
      phone = re.sub(r'\s*/\s*', '/', phone)
      ```
    * **Difficulty:** Easy (15 minutes).
  </Accordion>

  <Accordion title="Issue 2: Kochi GAIL Tender Regression - client_name_2_display (P2)">
    * **Symptoms:** Unit test `test_kochi_regression.py::test_kochi_tender_ground_truth_regression` fails:
      ```
      assert infosheet.get("client_name_2_display") == "Sabu Mathews"
      AssertionError: assert 'N/A' == 'Sabu Mathews'
      ```
    * **Root Cause:** In `volksAi/app/services/field_extractor.py` (`_parse_officer_table()`), the parser captures the first officer (Allan Tomy), but fails to parse the second officer (Sabu Mathews) due to an overly rigid table header regex that ignores multi-line officer rows.
    * **Fix:** Update row-splitting regex in `_parse_officer_table` to split on designated officer keywords (`General Manager`, `DGM`, `Manager`, `Engineer`).
    * **Difficulty:** Easy (30 minutes).
  </Accordion>

  <Accordion title="Issue 3: VolksAI Unit Test Failures from Scoping Refactor (P4)">
    * **Symptoms:** 12 tests fail across `test_llm_failure_handling.py` and `test_role1_prompt_examples.py`.
    * **Root Cause:**
      1. Commit `aee316ab` introduced `classify_anthropic_error` which changed how 401, 429, and timeouts are caught and converted into structured error dictionaries. The mocks in `test_llm_failure_handling.py` expected older exception types.
      2. Commit `aee316ab` also removed the 6,000-character blind context fallback. Synthetic text snippets in `test_role1_prompt_examples.py` did not contain explicit section headings, causing `extract_scoped_context` to return empty.
    * **Fix:** Update `test_llm_failure_handling.py` mocks to align with `classify_anthropic_error` and wrap synthetic test clauses with section headers (e.g. `TECHNICAL SPECIFICATIONS AND SPECIAL CONDITIONS`).
    * **Difficulty:** Medium (1 to 2 hours).
  </Accordion>

  <Accordion title="Issue 4: API Test String Mismatches (P3)">
    * **Symptoms:** `health.service.spec.ts` expects `"degraded"`, receives `"down"`. `operation-notification.service.spec.ts` has 4 string comparison failures.
    * **Root Cause:** Notification message templates were improved in production, but test assertions were not synchronized.
    * **Difficulty:** Easy (30 minutes).
  </Accordion>

  <Accordion title="Issue 5: Token Limit Truncation in Role 1">
    * **Symptoms:** Long payment clauses truncate at 600 max tokens (`stop_reason == "max_tokens"`), requiring an automatic 1,000-token retry that adds latency.
    * **Fix:** Raise baseline output token limit to 1,000 in `resolve_missing_fields_role1`.
    * **Difficulty:** Easy (15 minutes).
  </Accordion>

  <Accordion title="Issue 6: Separate Pipelines Parsing Same Tender Twice (P7)">
    * **Symptoms:** Info-Sheet extraction (`/extract`) and Checklist analysis (`/analyze-bidding-requirements`) run separate Claude calls, doubling latency and token cost.
    * **Fix:** Implement a unified `POST /extract-all` endpoint in VolksAI that extracts text once and orchestrates both field extraction and checklist generation.
    * **Difficulty:** Hard (2 to 3 days).
  </Accordion>
</AccordionGroup>
